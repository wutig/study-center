# 历史地名与坐标说明

这张复习地图的地名使用 Harvard / Fudan **China Historical GIS（CHGIS）** 项目经 Temporal Gazetteer（TGAZ）公开的结构化地名记录。历史名称与坐标来自同一条原始记录，没有把古地名随意贴到现代地点上。

- 供地图使用的筛选结果：`historical-places.json`，共 **658 个不重名、不重坐标的历史治所点**。

## 选取方法

统一使用 **1080 年**作为地名检索参考年，即北宋与辽等并立的时期。它适合提供《绍宋》故事背景附近时代的真实历史地名；不能把这些点全部解释为 1080 年北宋领土，也不能称它们是南宋当时的完整政区表。

过滤条件如下：

1. 原始 `OBJ_TYPE = POINT`。
2. 原始 `BEG <= 1080 <= END`。这两个字段表示该地名实例的存续区间。
3. `105 <= X <= 122`、`30.5 <= Y <= 41`。X 是经度，Y 是纬度，均为十进制度；范围覆盖地图北部需显示地名的区域。
4. 类型为县、府、州、军、监、直隶州、京師或城。排除道、路、政权、郡等本次不作为聚落治所名称使用的记录。

71,647 条原始记录经过上述筛选后剩 800 条。为避免同一坐标显示多个名称、或地图出现相同文字标签，再作两项确定性去重：相同名称只保留一条；经纬度各取小数点后四位后相同的坐标只保留一条。优先府/京師，其次州、军、监/城、县，同级按 `TGAZ_ID` 数字升序选择。最终为 658 点，包括 522 个县、97 个州、16 个府、19 个军，以及少量其他类型。

这种去重只为复习地图的标签清晰，并非说历史上没有同名异地或同城兼置州县的情况。

## 每个名称如何追溯

`historical-places.json` 的每条 `places` 记录保存：

| 字段 | 含义 |
| --- | --- |
| `id` / `source_id` | 原始 `TGAZ_ID`，未重编名称身份 |
| `name` | 原始 `NAME_SIM`，不改写成推测的古名 |
| `lon` / `lat` | 同一源记录的 `X` / `Y` |
| `valid_from` / `valid_to` | 同一源记录的 `BEG` / `END` |
| `feature_type` | 同一源记录的 `TYPE_SIM` |
| `source_line` | 本地源 CSV 行号，表头算第 1 行 |
| `source_url` | 官方 CSV 在 GitHub 的来源页 |
| `record_url` | 源 CSV 给出的地名详情 URI；旧服务链接可能因服务迁移失效 |
| `modernName` | 留空。原始 CSV 没有可靠的现代今址名称字段，不用近邻现代地名冒充历史名 |

例如京兆府、太原府、大名府、河南府、定州等，均有可核的原记录名称、时间区间与坐标。部分常见史名在这个版本的相应年代没有完整记录，地图应使用实际筛得的名称，不可为凑齐知名城市而将其就近改名。

原始 `PARTOF_*` 字段只给出数据库先检出的一个父级关系，可能跨不同年代。因此这里不将它显示成“1080 年直接隶属于某路/某州”，以免产生错误的年代对应。

## 地图怎样理解

地名点是历史聚落或治所的近似位置，**不是州县界线**。围绕点生成的地图分格只用于显示学习进度，面积与填色推进不代表真实行政区划、军事控制区或历史收复顺序。1080 年参考点与《绍宋》的虚构战役线路可以并存，但两者应在界面来源说明中分清。

点库规模固定，地图可以按地理分布从中选取种子。题库增减只应改变“已复习 / 总题数”的进度比例，不需要重新生成地名或地图网格。
